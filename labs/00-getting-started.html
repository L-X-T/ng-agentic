Getting Started with the Workshop

The on-ramp before the hands-on labs – and it's pre-work: do it before the workshop day. Get the workspace installed and running, and – just as important – pick the project you'll work on for the rest of the workshop.

Angular v22 Package manager pnpm 10 Node 22.22+/24.15+/26 (target 26) Est. time ~30 min When Pre-work Level beginner

About this lab

This is Lab 00 – the warm-up, done as pre-work before the workshop day. Before Lab 01, two things need to be in place: the project must install and run on your machine, and you need a project of your own to apply everything to.

The labs land better when every exercise moves a real goal forward. Carry a small, personal project through the workshop and each new piece of tooling – linter, style guide, MCP servers, the agent itself – lands on code you understand and want to improve.

Learning objectives

  • Clone this workspace and install its dependencies so the app builds and serves.
  • Confirm your toolchain: Node, a package manager, and at least one AI coding agent.
  • Choose a small project or work package to carry through the workshop.
  • Write down a concrete goal to aim for with an observable finish line.

Prerequisites

  • Node.js – Angular 22 supports 22.22+, 24.15+ or 26+; odd releases (23/25) are unsupported (node -v).
  • A package manager – npm ships with Node; this workspace standardizes on pnpm.
  • Git installed and configured (name + email).
  • At least one AI coding agent installed (e.g. Claude Code or Codex), plus a terminal and editor.

Steps

  1. Clone the repository and install the dependencies
  2. Verify your setup runs
  3. Choose your workshop project
  4. Write down your goal

1 Clone the repository and install the dependencies

Goal: get the workspace onto your machine and pull down everything it needs to build, serve, lint and format.

First clone the ng-agentic repository, then install the dependencies from package.json into node_modules.

Your task

Clone the repository, then install the dependencies from the repository root.

Show solution 
shellgit clone https://github.com/L-X-T/ng-agentic.git
cd ng-agentic
git switch setup   # or the branch your facilitator named
pnpm install --frozen-lockfile

The workspace commits a pnpm-lock.yaml, so use pnpm install --frozen-lockfile to resolve the exact same versions everyone else does. No pnpm yet? npm i -g pnpm@10.29.3 (or corepack enable on Node ≤ 24). The labs and the workshop scripts live on the chapter branches, not on main, so switch to setup (or the branch your facilitator named) before installing.

Checkpoint: the install finishes without errors and a node_modules/ folder exists at the repo root.

Tip: the labs link into the repository's Markdown guides (README.md, the numbered module files, the style guide). Read those on GitHub or in a Markdown preview (IDE, Typora) – opened directly in the browser they render as raw text and #section anchors are lost.

2 Verify your setup runs

Goal: prove the app serves and your toolchain is ready before you build on top of it.

Your task

  1. Start the dev server and open the app in a browser.
  2. Check your Node and package-manager versions.
  3. Confirm at least one AI coding agent is installed and can open this folder.
Show solution 
shellpnpm start         # serves on http://localhost:4200
node -v            # expect a supported version
pnpm -v            # match package.json#packageManager

Open http://localhost:4200 – you should see the running app; stop with Ctrl + C. Then confirm your agent is on your PATH (claude or codex) and can read this repository.

If it doesn't start

A failed pnpm start almost always traces back to Step 1 (re-run the install) or an unsupported Node version (node -v must be 22.22+, 24.15+ or 26+). Fix it here – every following lab assumes a working app.

Checkpoint: the app loads at localhost:4200, node -v reports a supported version, and your agent can open the project folder.

Preflight report

Run pnpm workshop:check in the workshop clone, on the setup branch or later (main has no workshop scripts). It checks build, lint, formatting and unit tests independently without repairing source or starting a server. Record the revision, versions and each result using the verification contract.

Confirm agent sign-in by asking it to read README.md. In your user-started app, check one visible interaction and the browser console. Browser automation is not installed at the setup checkpoint; record a manual smoke check. Keep failures and missing checks visible in the report, then resolve environment blockers before class.

3 Choose your workshop project

Goal: decide what you'll actually work on for the rest of the workshop – before we dive into the tooling.

Pick a project now. It doesn't have to be big – a focused work package is perfect. Keep it small (something you could meaningfully move in a workshop, not a quarter) and make it yours (work, a hobby, or a side project – the more you care, the more the labs stick).

Your task

Write down a short brief for the project you'll carry through the workshop. Capture:

  • Name – a working title.
  • What it is – one or two sentences on what you're building or improving.
  • Why it's yours – work, hobby, or side project, and why it matters to you.
  • Scope – what's deliberately in, and what you'll leave out for now.
Show solution – example project briefs
  • Recipe box – a side project: a small Angular app to save and search my recipes. Scope: list + detail + add form. Out: accounts, sync.
  • Team on-call dashboard – from work: one page showing who's on call this week. Scope: read-only view from a JSON feed. Out: editing the schedule.
  • Board-game score tracker – a hobby: log game-night scores and show a leaderboard. Scope: add a game, add scores, show standings. Out: stats over time.

The pattern: one clear feature set, a named reason it's yours, and an explicit "out of scope" so it stays small.

Checkpoint: you have a written, one-paragraph brief for a small project that's connected to your work, a hobby, or a side project.

4 Write down your goal

Goal: turn the project into a concrete target you can aim at with an observable finish line.

A project is a direction; a goal is a finish line. Writing it down – even an ambitious one – gives every lab something to push toward and makes progress obvious.

Your task

Write a single sentence stating what you want to have achieved by the end of the workshop. Optionally add a "stretch" version that's deliberately bigger than what feels realistic.

Show solution – example goals
ProjectRealistic goalStretch goal
Recipe box Have an agent build the list + detail views following project conventions. Ship an accessible, tested app with search and tagging.
On-call dashboard Render the current on-call person from a static JSON feed. Live data, dark mode, and a one-click "page me" button.
Score tracker Add scores and show a leaderboard for one game. Multi-game stats, charts, and shareable links.

Keep the goal visible while you work – it's your reference for whether the agentic setup is actually moving your project forward.

Checkpoint: you've written one sentence stating your goal (and, optionally, a stretch goal).
